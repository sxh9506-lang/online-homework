# Demo 模式安全边界验收用例

本文件是 QA 专用验收范围，依据 [PR #8](https://github.com/sxh9506-lang/online-homework/pull/8) 中 `docs/mvp-contract.md`、`backend/README.md` 和 `ops/ci-test-deploy.md` 记录的已批准要求。它定义需要验证的行为，不表示运行时保护已经实现或通过验收。

## 测试安全要求

- 仅在与生产完全隔离的测试环境和专用测试数据库中执行；不得使用真实学生资料、真实用户账号或生产凭据。
- 测试账号只用虚构身份。密码只能由测试环境的 Secrets 提供；测试夹具、命令行参数、仓库文件、普通配置变量和公开材料不得保存密码值。
- 断言可在测试进程内检查密码编码器的匹配结果和持久化记录，但不得将明文密码、密码哈希、验证令牌或可复用凭据写入日志、响应、截图、测试报告或 CI 工件。失败信息只报告用例 ID 和脱敏状态。
- 必须实际启动应用并检查数据库状态及 HTTP 行为。仅检查配置文件或源码字符串不算通过。

## P0：启用 demo 前必须通过

### DEMO-01 默认关闭且不预置账号

**步骤：** 使用全新测试数据库，在测试运行配置中分别省略 `DEMO_MODE` 和显式设为 `false` 后启动应用；检查有效配置、种子数据及认证行为。

**通过标准：** 两种情况下有效值均为 `false`；应用不创建任何 demo 种子账号或相关演示数据，且种子账号不能通过认证。默认配置不得悄悄启用 demo 模式。

### DEMO-02 种子账号仅为虚构 `.invalid` 身份

**步骤：** 在隔离的测试环境显式开启 `DEMO_MODE=true` 并运行批准的演示种子流程；逐条检查写入数据库的种子账号。另提供一个含非 `.invalid` 邮箱的种子配置，验证拒绝路径。

**通过标准：** 所有预置账号均为虚构的教师或学生账号，规范化后的邮箱域名以 `.invalid` 结尾；没有其他角色、真实账号或来自真实用户的数据。遇到非 `.invalid` 邮箱时，启动或种子事务必须失败关闭，且数据库中不留下部分种子账号。验收报告只记录脱敏的账号标识与计数，不记录邮箱值。

### DEMO-03 测试 Secrets 注入、仅存哈希且不泄露

**步骤：** 在隔离测试环境中通过受保护的测试环境 Secrets 提供种子账号密码，并开启 demo 种子流程。检查持久化凭据、使用密码编码器在进程内验证匹配；同时检查 API 响应、应用日志、CI 日志及工件。再移除必需的测试 Secret 重启一次。

**通过标准：** 密码只来自测试环境 Secrets；数据库只保存密码编码器生成的单向哈希，哈希与原始值不同且可由编码器匹配。API、应用/CI 日志、报告、工件和公开文档均不包含原始密码或哈希。缺少必需 Secret 时必须失败关闭，不得使用默认口令或继续创建可登录账号；诊断信息不得回显 Secret。

### DEMO-04 生产环境拒绝以 demo 模式启动

**步骤：** 使用生产运行配置启动应用并设置 `DEMO_MODE=true`；观察进程退出状态、监听端口、健康/就绪状态及数据库写入。再以 `DEMO_MODE=false` 和未设置该值各启动一次作为对照。

**通过标准：** 生产配置为 `true` 时，应用必须在对外提供服务前启动失败；端口不得接受业务请求，健康/就绪检查不得报告成功，且不得写入 demo 种子数据。错误信息应说明配置不允许，但不得包含密码或其他 Secret。对照配置不得创建 demo 种子账号。

### DEMO-05 Demo 模式不得绕过自助注册邮箱验证

**步骤：** 在隔离测试环境开启 demo 模式，并将邮件发送接入仅供测试使用的邮件捕获器。使用一个新的虚构身份走完整的自助注册流程；在邮箱未验证前尝试登录及访问需认证接口，再分别提交无效/过期和有效的验证令牌。使用有效令牌后再次登录，并检查该账号及另一个未验证账号的状态。

**通过标准：** 自助注册账号在完成邮箱验证前不能取得有效登录会话或访问需认证接口；demo 模式不得将其自动标为已验证。无效或过期令牌按接口合同拒绝（`400`），且不改变验证状态；有效令牌只验证对应账号并按合同成功返回（`204`），此后该账号才可正常登录。邮件捕获器中的验证令牌以及任何凭据均不得出现在日志或验收材料中。

## 发布门槛

以上所有 P0 用例必须在实现 demo 种子和生产启动保护后全部通过，才可在获批的隔离测试演示环境启用 `DEMO_MODE`。在实现及测试完成前，应将相关用例标记为未通过或未实现，不得宣称生产启动保护已生效。
