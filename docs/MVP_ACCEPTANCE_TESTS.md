# 在线家庭作业系统 MVP 验收用例

## 验收目标

在 3 个工作日内验证教师—学生网页闭环：教师创建班级并布置作业，已注册学生被教师按登录邮箱添加后提交附件，教师批改并发布，学生只查看自己的提交和当前已发布反馈。优先级最高的是角色/对象级越权、私有文件安全、上传与重交、逾期提交和批改可见性。验收必须调用后端接口或真实页面完成，并直接验证服务端拒绝结果；仅检查前端是否隐藏按钮不算通过。

测试使用专用虚构账号和对象存储测试桶，不使用真实学生资料、真实作业文件或生产凭据。每次运行记录构建版本、测试账号角色、请求/响应（脱敏）和结果；不得记录或粘贴签名 URL、令牌或私有对象 key。

## 测试数据

- `T1`：教师账号，拥有班级 `C1`；`T2`：另一教师，拥有班级 `C2`。
- `S1`、`S2`：已验证登录邮箱并加入 `C1` 的学生；`S3`：仅加入 `C2` 的学生；`S0`：尚未注册的邮箱。
- `A1`：`C1` 的已发布作业；`A-draft`：`C1` 的草稿作业。需要设置到期行为时，分别准备开放逾期提交和 `closeAfterDeadline=true` 的作业。
- 文件夹具使用真实内容与匹配 MIME 的 PDF/PNG/DOCX 等允许类型，以及大小为 `20,971,519`、`20,971,520`、`20,971,521` 字节的文件，另准备第二个附件、声明类型与真实内容不符和不支持类型的文件。

## P0：试用前必须通过

### 身份、班级与授权

| ID | 验收步骤 | 通过标准 |
| --- | --- | --- |
| AUTH-01 当前身份 | 分别以 T1、S1 登录并调用 `GET /api/v1/me`；再以无效或缺失凭据调用。 | 已登录用户仅得到自己的 ID 和角色；未认证请求被拒绝（契约指定 `401`）。服务端身份来自认证主体，不接受客户端提交的 user/role 作为授权依据。真实学生数据接入前，测试/部署环境已启用邮箱验证。 |
| CLASS-01 按邮箱精确添加学生 | T1 通过 `POST /classes/{classId}/members` 在 C1 中添加 S1 已注册的登录邮箱；再添加 S0 的邮箱。 | 已存在的学生账号关联到 C1；不存在时返回稳定错误码 `STUDENT_ACCOUNT_NOT_FOUND` 并提示先注册，不发送邀请邮件、不自动创建账号、不提供入班码。邮箱验证后的真实学生账号才可用于真实数据试用。 |
| AUTHZ-01 教师所有权隔离 | T2 尝试读取、修改 T1 的 C1、作业、提交、附件和批改记录；学生尝试创建班级、发布作业、查看教师提交列表或批改。 | 所有越权请求由服务端拒绝；对象不可见时可统一返回 `403` 或不泄露存在性的 `404`，但同一类接口策略需一致。不能因知道 UUID 而获得访问权。 |
| CLASS-02 移除学生 | T1 移除 S1 的 C1 成员关系；S1 再请求 C1 作业、创建新提交、下载 C1 附件。 | 移除后撤销后续班级内容访问权；已生成的历史记录保留，不因移除被删除。其他班级成员及教师的权限不受影响。 |

### 作业、附件与学生提交

| ID | 验收步骤 | 通过标准 |
| --- | --- | --- |
| ASSIGN-01 草稿与发布边界 | T1 创建草稿并编辑；S1 通过列表和直接 ID 请求读取；T1 发布后重试。 | 草稿只对所属教师可见，学生不能通过列表或猜测/持有 ID 读取；发布后仅 C1 成员可见。已发布作业不可被草稿更新接口静默覆盖。 |
| ASSIGN-02 跨班访问 | S3 请求读取 A1、列出 C1 作业或提交 A1；T2 请求修改/发布 A1。 | 目标班级以外的学生及非所属教师均不能借直接资源 ID 访问或操作。 |
| FILE-01 附件限制与内容校验 | 对作业附件和提交附件分别测试 1 个合法文件、第二个附件，以及大小为 `20,971,519`、`20,971,520`、`20,971,521` 字节的文件；同时检查上传界面和机器可读 API 文档中的上限说明。测试允许列表外类型，以及扩展名/MIME 与实际文件内容不匹配。 | 每个作业、每个提交最多 1 个附件；上限为 `20 MiB`，即 `20 × 1024 × 1024 = 20,971,520` 字节。上传界面和 API 文档都必须明确写出 `20 MiB` 及其字节数，不得只写含义不明的“20 MB”。不超过上限（含恰好 `20,971,520` 字节）的文件可上传；`20,971,521` 字节返回 `FILE_TOO_LARGE`。允许 PDF、JPG、PNG、DOCX、XLSX、PPTX；不支持类型返回 `UNSUPPORTED_FILE_TYPE`，内容不符返回 `FILE_CONTENT_MISMATCH`；拒绝的文件不形成可见附件或提交版本。服务端按实际字节数和对象内容校验，不只信任浏览器文件名或 MIME 声明。 |
| FILE-02 私有存储及签名链接 | 未授权账号请求其他班级/他人附件的上传意图或下载链接；授权者通过 `POST /upload-intents/{uploadId}/upload-url` 获取链接，在真实等待 URL 过期后重新签发；尝试传入任意 object key。 | 未授权时不签发 URL；对象存储不可匿名公开访问。签名链接仅限一个对象和一种操作，短时有效且到期后不可复用。集成测试使用生产 `S3PrivateObjectStorage` 与真实 AWS SDK `S3Presigner`、本地 dummy 凭据和保留域名 `s3.invalid`，检查 URL 中 `X-Amz-Expires` 与配置 TTL 一致并在墙钟等待后过期，再确认刷新签名的到期时间更晚；测试不访问 S3，只验证签名参数与刷新行为，不声称验证服务端对过期签名的实际拒绝。授权刷新不创建或改变意图状态；API 不接受客户端任意指定 object key；上传/下载均先做服务端对象级授权。 |
| SUB-01 上传幂等键 | S1 调用 `POST /assignments/{assignmentId}/submissions` 创建 A1 提交上传，携带 `Idempotency-Key: K1`；以相同 payload 并发重试；然后用同 key 和不同 payload 重试；在独立授权接口重复签发上传 URL。 | 同一用户、同一作业、同一 key 的创建响应保持完全稳定，只返回相同 `uploadId` 与 `status`，不含 URL 或 `expiresAt`，且数据库仅有一个意图；不同 payload 返回 `409 IDEMPOTENCY_KEY_CONFLICT`，不新增或改变意图。不同用户/作业的 key 空间互不串用，不能借 key 读取或复用他人的记录。独立 URL 签发/重试不创建或改变意图状态；并发创建与冲突场景须在 PostgreSQL 16 上通过应用服务验证。 |
| SUB-02 未就绪、校验失败与 complete 幂等 | 对上传记录调用 `POST /submissions/{uploadId}/complete` 时确保对象尚未到达；确认无可见提交版本后补传对象并重试；成功后重复调用 complete；另对无效对象调用 complete；在附件存储禁用时重试 same-payload replay、不同 payload 冲突、pending/已完成 complete、URL 签发及不存在资源的 complete/download。 | 存储启用时，未到齐返回可重试 `UPLOAD_NOT_READY`，不分配版本号、不生成可见提交；首次校验成功后原子性分配版本号和服务器 UTC `completedAt`；相同上传记录重复 complete 返回同一结果且不增加版本。存储禁用/不可用时，存储 guard 必须先于幂等重放、payload 冲突、状态及资源查询，所有附件创建、签 URL、complete（含已完成重放）及 download 请求均返回 `503 ATTACHMENTS_UNAVAILABLE`，且不改变意图或创建版本。校验失败返回对应稳定错误码且不生成提交版本。 |
| SUB-03 截止、时区与关闭提交 | 使用可控服务器时钟，令上传校验成功时的 `completedAt` 分别早于、恰好等于和晚于 `dueAt`；对开放逾期提交的作业和 `closeAfterDeadline=true` 的作业都覆盖截止等值与截止后场景。班级时区设为 `Asia/Tokyo`，检查同一 `dueAt` instant 的页面展示。 | `completedAt` 是对象上传完成并通过服务端校验的服务器时间；服务端将 `completedAt` 与 `dueAt` 按 UTC instant 比较。`completedAt < dueAt` 和 `completedAt == dueAt` 均按时，`late=false`；只有 `completedAt > dueAt` 才逾期。开放逾期提交的作业在截止后仍接受并标为 `late=true`；`closeAfterDeadline=true` 的作业在截止 instant（含相等）可提交，超过截止时刻拒绝新提交并返回 `ASSIGNMENT_CLOSED`。界面按班级 IANA 时区展示截止时间；不得用客户端时钟决定是否逾期。 |
| SUB-04 重交版本及本人记录 | S1 对 A1 完成首次提交，再用新的 key 完成重交；S2、S3 分别尝试读取 S1 的版本。 | 重交产生新的递增版本，早期文件、文本和时间记录不被覆盖；教师列表能查看本班提交及各版本。`GET /assignments/{assignmentId}/my-submissions` 只返回当前学生自己的版本及允许返回的当前已发布结果；其他学生不能读取。 |

### 批改与反馈

| ID | 验收步骤 | 通过标准 |
| --- | --- | --- |
| GRADE-01 教师批改权限与历史 | T1 查看 A1 提交，为 S1 建立批改草稿并查询批改历史；T2 和学生尝试访问教师历史或创建批改。 | 只有拥有该班级的教师可查看/新建批改；每次新批改追加一条历史记录，不覆盖旧记录。学生不能读取草稿或历史。 |
| GRADE-02 发布可见性 | T1 创建批改草稿；S1 请求当前结果；T1 发布后 S1 再请求；随后 T1 创建并发布新一版。S2 请求 S1 的结果。 | 草稿发布前学生看不到评分/反馈；发布后 S1 仅看到自己当前已发布的结果。新版本发布后当前结果切换至新版本，旧记录仍供教师查阅；S2 不能读取 S1 的结果。 |

## P1：边界与回归

- 对同一提交以相同 key 重试但更换文件大小、内容或元数据，验证 `IDEMPOTENCY_KEY_CONFLICT` 及无副作用；确认失败响应不泄露对象 key 或他人资源是否存在。
- 对未登录、其他班级学生、同班其他学生、已移除成员和另一教师分别检查作业附件及提交附件下载权限；检查过期 URL、重复上传完成、客户端篡改 ID/object key 的拒绝行为。
- 验证页面在班级时区显示截止时间，并在服务器重启或数据库重读后仍保留 UTC 时间、版本顺序、逾期标记和批改历史。

## 接口合同依据与已确认边界

验收以最新产品决定及 PR #1 中的 `docs/architecture/api-contract.md` 为准。该合同已明确：使用 `POST /classes/{classId}/members` 按已注册学生邮箱添加成员；创建提交须带 `Idempotency-Key`，同一用户、作业和 key 返回同一上传记录；对象上传完成且服务端校验通过后才生成正式提交版本；未就绪返回可重试的 `UPLOAD_NOT_READY`，重复 complete 返回原结果且不重复生成版本。上述规则均已反映在本文件，不再列为待解决或阻塞差异。

截止及附件上限是已确认规则，不再作为产品待确认项：服务端以校验成功时生成的 UTC `completedAt` 与 UTC instant `dueAt` 比较，仅 `completedAt > dueAt` 逾期；截止时刻相等按时。截止时间按班级时区展示。前端界面和机器可读 API 文档对文件上限须统一标为 `20 MiB (20 × 1024 × 1024 = 20,971,520 bytes)`；前后端按同一字节上限执行。PR #1 的 API 合同和实现如有不一致，应在发布前按这些已确认规则对齐。

测试环境仍需准备可控时钟、专用测试账号/邮箱验证流程和私有对象存储；这些准备不代表在 MVP 增加通知或生产账号管理能力。

## 通过门槛

试用版发布前必须全部通过 P0，特别是 AUTHZ-01、CLASS-02、FILE-01/02、SUB-01–04 和 GRADE-01/02。P1 结果应随试用版本记录并进入后续迭代清单；不得将已确认的截止等值或 20 MiB 边界退回为待定规则。
