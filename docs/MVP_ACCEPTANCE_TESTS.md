# 在线家庭作业系统 MVP 验收用例

## 验收目标

在 3 个工作日内验证教师—学生网页闭环：教师创建班级并布置作业，已注册学生被教师按登录邮箱添加后提交附件，教师批改并发布，学生只查看自己的提交和当前已发布反馈。优先级最高的是角色/对象级越权、私有文件安全、上传与重交、逾期提交和批改可见性。验收必须调用后端接口或真实页面完成，并直接验证服务端拒绝结果；仅检查前端是否隐藏按钮不算通过。

测试使用专用虚构账号和对象存储测试桶，不使用真实学生资料、真实作业文件或生产凭据。每次运行记录构建版本、测试账号角色、请求/响应（脱敏）和结果；不得记录或粘贴签名 URL、令牌或私有对象 key。

## 测试数据

- `T1`：教师账号，拥有班级 `C1`；`T2`：另一教师，拥有班级 `C2`。
- `S1`、`S2`：已验证登录邮箱并加入 `C1` 的学生；`S3`：仅加入 `C2` 的学生；`S0`：尚未注册的邮箱。
- `A1`：`C1` 的已发布作业；`A-draft`：`C1` 的草稿作业。需要设置到期行为时，分别准备开放逾期提交和 `closeAfterDeadline=true` 的作业。
- 文件夹具使用真实内容与匹配 MIME 的 PDF/PNG/DOCX 等允许类型，以及超限、第二个附件、声明类型与真实内容不符和不支持类型的文件。

## P0：试用前必须通过

### 身份、班级与授权

| ID | 验收步骤 | 通过标准 |
| --- | --- | --- |
| AUTH-01 当前身份 | 分别以 T1、S1 登录并调用 `GET /api/v1/me`；再以无效或缺失凭据调用。 | 已登录用户仅得到自己的 ID 和角色；未认证请求被拒绝（契约指定 `401`）。服务端身份来自认证主体，不接受客户端提交的 user/role 作为授权依据。真实学生数据接入前，测试/部署环境已启用邮箱验证。 |
| CLASS-01 按邮箱精确添加学生 | T1 在 C1 中添加 S1 已注册的登录邮箱；再添加 S0 的邮箱。 | 已存在的学生账号关联到 C1；不存在时返回稳定错误码 `STUDENT_ACCOUNT_NOT_FOUND` 并提示先注册，不发送邀请邮件、不自动创建账号、不提供入班码。邮箱验证后的真实学生账号才可用于真实数据试用。 |
| AUTHZ-01 教师所有权隔离 | T2 尝试读取、修改 T1 的 C1、作业、提交、附件和批改记录；学生尝试创建班级、发布作业、查看教师提交列表或批改。 | 所有越权请求由服务端拒绝；对象不可见时可统一返回 `403` 或不泄露存在性的 `404`，但同一类接口策略需一致。不能因知道 UUID 而获得访问权。 |
| CLASS-02 移除学生 | T1 移除 S1 的 C1 成员关系；S1 再请求 C1 作业、创建新提交、下载 C1 附件。 | 移除后撤销后续班级内容访问权；已生成的历史记录保留，不因移除被删除。其他班级成员及教师的权限不受影响。 |

### 作业、附件与学生提交

| ID | 验收步骤 | 通过标准 |
| --- | --- | --- |
| ASSIGN-01 草稿与发布边界 | T1 创建草稿并编辑；S1 通过列表和直接 ID 请求读取；T1 发布后重试。 | 草稿只对所属教师可见，学生不能通过列表或猜测/持有 ID 读取；发布后仅 C1 成员可见。已发布作业不可被草稿更新接口静默覆盖。 |
| ASSIGN-02 跨班访问 | S3 请求读取 A1、列出 C1 作业或提交 A1；T2 请求修改/发布 A1。 | 目标班级以外的学生及非所属教师均不能借直接资源 ID 访问或操作。 |
| FILE-01 附件限制与内容校验 | 对作业和提交附件分别测试 1 个合法文件、第二个附件、20 MiB 边界、超过 20 MiB、允许列表外类型，以及扩展名/MIME 与实际文件内容不匹配。 | 每个作业、每个提交最多 1 个附件；按当前 OpenAPI 数值上限 `20,971,520` 字节（20 MiB）验收。允许 PDF、JPG、PNG、DOCX、XLSX、PPTX。超限返回 `FILE_TOO_LARGE`，不支持类型返回 `UNSUPPORTED_FILE_TYPE`，内容不符返回 `FILE_CONTENT_MISMATCH`；拒绝的文件不形成可见附件或提交版本。服务端检查实际对象，不只信任浏览器文件名或 MIME 声明。产品文案“20 MB”与 20 MiB 的精确边界需确认，十进制/二进制差额测试暂列 P1。 |
| FILE-02 私有存储及签名链接 | 未授权账号请求其他班级/他人附件的上传意图或下载链接；授权者获取链接后测试正常使用及过期后重用；尝试传入任意 object key。 | 未授权时不签发 URL；对象存储不可匿名公开访问。签名链接仅限一个对象和一种操作，短时有效且到期后不可复用。API 不接受客户端任意指定 object key；上传/下载均先做服务端对象级授权。 |
| SUB-01 上传幂等键 | S1 为 A1 创建提交上传，携带 `Idempotency-Key: K1`；在响应丢失后，以同一 S1、同一作业和同一 key 重试；再以另一学生或另一作业使用 K1。 | 同一用户、同一作业、同一 key 的重试返回同一上传记录，不重复创建版本；不同用户/作业的 key 空间互不串用，不能借 key 读取或复用他人的记录。若同 key 对应不一致请求，按接口契约返回 `IDEMPOTENCY_KEY_CONFLICT`。 |
| SUB-02 未就绪、校验失败与 complete 幂等 | 上传对象尚未到达时调用 complete；确认无可见提交版本后补传对象并重试；成功后重复调用 complete；另对无效对象调用 complete。 | 未到齐时返回可重试 `UPLOAD_NOT_READY`，不分配版本号、不生成可见提交。首次服务端校验成功后原子性分配版本、记录 UTC `submittedAt` 并计算逾期状态。相同上传记录的重复 complete 返回同一结果、不再增加版本。校验失败返回对应稳定错误码且不生成提交版本。 |
| SUB-03 截止、时区与关闭提交 | 使用可控测试时钟：分别在截止前和截止后完成提交；为另一作业设置 `closeAfterDeadline=true` 后，在截止后提交。班级时区设为 `Asia/Tokyo`，检查相同截止 instant 的展示。 | 截止前 `isLate=false`；截止后且仍开放时接受提交并标为 `isLate=true`；关闭后拒绝新提交，错误码 `ASSIGNMENT_CLOSED`。比较使用服务端 UTC instant，截止时间按班级 IANA 时区显示；不得使用客户端时钟决定是否逾期。 |
| SUB-04 重交版本及本人记录 | S1 对 A1 完成首次提交，再用新的 key 完成重交；S2、S3 分别尝试读取 S1 的版本。 | 重交产生新的递增版本，早期文件、文本和时间记录不被覆盖；教师列表能查看本班提交及各版本。`GET /assignments/{assignmentId}/my-submissions` 只返回当前学生自己的版本及允许返回的当前已发布结果；其他学生不能读取。 |

### 批改与反馈

| ID | 验收步骤 | 通过标准 |
| --- | --- | --- |
| GRADE-01 教师批改权限与历史 | T1 查看 A1 提交，为 S1 建立批改草稿并查询批改历史；T2 和学生尝试访问教师历史或创建批改。 | 只有拥有该班级的教师可查看/新建批改；每次新批改追加一条历史记录，不覆盖旧记录。学生不能读取草稿或历史。 |
| GRADE-02 发布可见性 | T1 创建批改草稿；S1 请求当前结果；T1 发布后 S1 再请求；随后 T1 创建并发布新一版。S2 请求 S1 的结果。 | 草稿发布前学生看不到评分/反馈；发布后 S1 仅看到自己当前已发布的结果。新版本发布后当前结果切换至新版本，旧记录仍供教师查阅；S2 不能读取 S1 的结果。 |

## P1：边界与回归

- 在 `20,000,000` 字节与 `20,971,520` 字节之间补测文件边界；确定产品所称“20 MB”采用十进制还是按 OpenAPI 数值对应的 20 MiB。决定前保留当前 OpenAPI 数值作为暂行断言，不把两种单位视为相同。
- 对同一提交以相同 key 重试但更换文件大小、内容或元数据，验证 `IDEMPOTENCY_KEY_CONFLICT` 及无副作用；确认失败响应不泄露对象 key 或他人资源是否存在。
- 对截止时间前 1 秒、准确等于截止 instant、后 1 秒分别验证。前后边界应符合 UTC instant 规则；“恰好等于截止时间”当前尚未明确由 `>` 还是 `>=` 判逾期，定规则前将该边界标为待确认，不作为发布阻塞的隐式假设。
- 对未登录、其他班级学生、同班其他学生、已移除成员和另一教师分别检查作业附件及提交附件下载权限；检查过期 URL、重复上传完成、客户端篡改 ID/object key 的拒绝行为。
- 验证页面在班级时区显示截止时间，并在服务器重启或数据库重读后仍保留 UTC 时间、版本顺序、逾期标记和批改历史。

## 接口合同同步项

测试行为以最新产品决定及 `docs/architecture/api-contract.md` 为准。该架构 API 文档和当前 `docs/openapi.yaml` 草案存在明显差异；实现端到端验收前应统一 OpenAPI，至少核对：

1. 注册/登录、邮箱验证状态，以及按邮箱添加和移除班级成员的接口与字段；
2. 上传申请所需的 `Idempotency-Key`、直传完成接口、`UPLOAD_NOT_READY` 和重复 complete 行为；
3. 提交逾期字段名：API 草案使用 `isLate`，OpenAPI schema 目前为 `late`；
4. 批改资源路径：API 草案使用 `reviews`，OpenAPI 当前使用 `grades`；
5. 作业/提交附件上传申请路径、教师关闭提交的接口，以及错误响应中的稳定 `code` 字段；错误码至少包含 `STUDENT_ACCOUNT_NOT_FOUND`、`IDEMPOTENCY_KEY_CONFLICT`、`UPLOAD_NOT_READY`、`FILE_TOO_LARGE`、`UNSUPPORTED_FILE_TYPE`、`FILE_CONTENT_MISMATCH`、`ASSIGNMENT_CLOSED`、`ASSIGNMENT_NOT_PUBLISHED`、`FORBIDDEN`；
6. 文件大小产品文字“20 MB”与 OpenAPI 的 `20,971,520` 字节上限是否都代表 20 MiB。

在这些名称统一前，验收断言按业务行为和稳定错误码执行，不因路径或字段命名差异误报功能失败。测试环境需有可控时钟、专用测试账号/邮箱验证流程和私有对象存储；这些准备不代表要求在 MVP 增加通知或生产账号管理能力。

## 通过门槛

试用版发布前必须全部通过 P0，特别是 AUTHZ-01、CLASS-02、FILE-01/02、SUB-01–04 和 GRADE-01/02。P1 中尚待产品确认的精确截止等值边界不得由实现团队自行补定；其余 P1 结果应随试用版本记录，进入后续迭代清单。
