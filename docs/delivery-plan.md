# 三工作日 MVP 交付计划

目标是尽快取得可试用反馈，而非先做完长期规划。采用纵向切片，接口与代码按小 PR 集成；未完成/阻塞项在当天 PR 和状态中公开，不把安全关键项留到演示后。

| 工作日 | 产品/架构 | 后端 | 前端 | 测试 | 运维/交付 |
|---|---|---|---|---|---|
| 1：定接口、搭底座 | 锁定 MVP、状态转换、错误码与 API 契约；评审 PR | Java 25 / Spring Boot 应用骨架、PostgreSQL/Flyway、认证/角色、班级/成员与对象权限；作业草稿/发布端点起步 | 登录与角色导航、教师班级/作业页面、学生作业列表页面骨架，尽早按 API 契约联调 | 核对角色/权限、班级成员与草稿可见性验收条件；建立测试清单 | PR 检查（Java 25、前端 lint/build、测试）、本地依赖编排与测试环境部署方案；暴露缺少的环境变量/凭据 |
| 2：跑通提交与批改 | 快速澄清阻塞决策、验收主流程 | 私有存储预签名上传、幂等提交意图、complete 校验/版本/逾期，教师批改与学生只读已发布反馈 | 学生提交/重交、教师提交列表/批改/发布、学生反馈页，与真实 API 联调 | 正反向 API/集成测试：完成提交、重复上传请求和 complete、逾期与越权、发布可见性 | 接好测试配置/私有存储适配，保证 CI 在 PR 中运行 |

## 集成纪律

- 后端、前端、测试、运维分别使用聚焦分支和 PR；不直接在共享工作分支互相覆盖。
- 每个 PR 只覆盖单一模块/流程，描述 API 变更、权限影响、测试方法、部署影响和未解决项。
- PR 检查未过不合并。API 不兼容变更需先更新契约，再由前后端同步改动。
- 每天通过可运行的端到端切片验收；优先修复会阻断教师—学生主流程或对象级安全的缺陷。
- 测试环境使用专用虚构账号。接真实学生前必须启用验证过的登录邮箱；绝不在公开仓库放入真实记录、账号或秘密。

## 短期演示数据库方案

- 演示环境数据库目标已选 Render 免费 PostgreSQL：1 GB，创建后 30 天到期、无备份，到期后有 14 天宽限期再删除。
- 该服务仅用于短期虚构演示数据，不存真实学生资料或任何唯一副本；当前只更新方案，不创建 Render 资源。

## 角色工作包

- **产品/项目经理**：维护本文件与 MVP 验收边界；跟踪每天的端到端演示结果、未决事项和阻塞；依据真实试用反馈决定下一迭代。
- **架构师**：维护模块/API/状态与权限边界；评审跨模块接口和存储安全方案；防止为首版引入微服务等非必要复杂度。
- **后端**：按契约实现认证、班级成员、作业、提交、批改、附件端点及服务端对象级授权；补状态/迁移与集成测试。
- **前端**：教师与学生主流程页面、角色可见字段、上传状态/错误提示与 API 对接；前端控制不作为安全边界。
- **测试**：验收用例与权限/幂等/截止时间/上传负向测试；关键路径 PR 必须有自动化验证。
- **运维**：PR 检查、环境配置模板、测试环境部署/健康检查/回滚文档；密钥只通过环境秘密管理提供。

## 需及早确认的外部依赖

测试环境 URL/部署平台、对象存储兼容服务与测试凭据、测试账号的邮箱验证方案、评分上限/舍入方式尚需确认。上述信息不足时先用本地开发替身/专用测试账号推进；不得将私有附件暴露为公开 URL，也不得假装完成了真实环境部署。
