# MVP v0.1 产品范围

## 目标

在 3 个工作日内交付可试用的教师—学生网页闭环，尽快验证核心流程并据此继续迭代：**老师布置 → 学生上传提交 → 老师批改 → 学生查看反馈**。首版优先保证流程真实可用与服务端权限正确，不追求大而全。

## 用户与流程

**教师**登录后可创建并管理自己的班级、按学生登录邮箱精确添加已有学生账号、创建作业草稿并发布、查看班级提交、记录评分与文字反馈并发布结果。教师可以移除班级学生。测试环境使用预置教师账号；教师生产账号的开通方式待确认。

**学生**注册/登录后仅能访问自己所属班级已发布的作业；每次重新提交都形成独立版本，能查看自己的提交状态和版本，并只能查看自己当前已发布的批改结果。

注册、登录和班级成员维护的规则：

- 学生须先注册/登录，教师按登录邮箱精确添加已有学生账号；邮箱不匹配时返回“请先注册”，MVP 不发送邀请邮件、不提供自助入班码。
- 接入真实学生前必须启用登录邮箱验证；测试环境使用专用测试账号。
- 同一作业可多次提交，历史版本不可被新提交覆盖。

## 首版规则

- 作业可保存为草稿；学生端不显示草稿，发布后目标班级学生可见。
- 截止时间以班级 IANA 时区展示，数据库保存 UTC。截止后默认仍可提交但标记逾期；教师可关闭提交，关闭后拒绝新提交。
- 每个作业最多 1 个附件，每次提交最多 1 个附件；每个附件不超过 20 MB。首版支持 PDF、JPG、PNG、DOCX、XLSX、PPTX。
- 文件只进私有对象存储。上传/下载先经服务端做资源权限检查，再返回短时签名 URL；客户端不能指定对象存储 key。
- 评分/反馈保存与发布分开。学生只看到当前已发布结果；教师每次批改历史保留。
- 提交上传须提供 `Idempotency-Key`。同一用户、作业和 key 的重试返回同一上传记录；完成上传的重复调用返回相同结果。
- 对象未上传完成时返回可重试的 `UPLOAD_NOT_READY`，不生成可见提交版本。对象大小/类型校验失败时返回稳定错误码并拒绝文件。仅首次完成校验成功时分配提交版本号、记录 UTC 提交时间并计算逾期状态。

## MVP 暂不做

家长端、移动 App、批量导入、邮件通知、统计报表、自动判题、自助入班码和复杂评分量表不进入首版。

## 工作日交付节奏

| 时点 | 可验收结果 |
|---|---|
| 第 1 个工作日 | 定版接口/模块边界；可运行工程、登录与角色权限、班级/成员基础；教师可创建作业草稿并发布，学生能看到本班已发布作业。 |
| 第 2 个工作日 | 学生上传、完成校验、重复提交保留版本；教师查看提交、批改并发布评分/反馈；学生能查看自己的当前已发布结果。 |
| 第 3 个工作日 | 前后端联调、核心功能和越权/上传冒烟测试、修复阻塞问题、部署到测试环境并用专用账号走通闭环。 |

每天结束以可演示的纵向切片为准；若部署凭据或目标环境未准备好，应在第 1 天尽早暴露依赖，而不是最后一天才发现。

## 待产品确认（不阻塞接口骨架）

- 评分是否需要满分值/等级制；MVP 先按“数值分数 + 文字反馈”建模，范围和舍入规则待确认。
- 测试环境的部署目标、测试账号创建/邮箱验证流程、对象存储服务与保留周期需在接入真实测试前确认。
